    Note over U,W: 🔍 Step 2: SEARCH 搜索
    Note over U,W: ══════════════════════════════════════════════════════════════

    loop 每个 depth level (depth = 2)
        loop 每个 plan step (steps = 3-5)
            S->>L: 生成搜索查询
            Note right of L: 输入：step + 累积上下文
+ 已搜索查询（避免重复）
输出：3-5 个查询
            L-->>S: ["query1", "query2", "query3"]

            par 并行搜索（最多3个并发）
                S->>W: web_search("query1", topK=4)
                W-->>S: [{title, url, snippet}, ...]
            and
                S->>W: web_search("query2", topK=4)
                W-->>S: [{title, url, snippet}, ...]
            and
                S->>W: web_search("query3", topK=4)
                W-->>S: [{title, url, snippet}, ...]
            end

            par 并行获取（深入阅读）
                S->>W: web_fetch(url1)
                W-->>S: {title, text, truncated}
            and
                S->>W: web_fetch(url2)
                W-->>S: {title, text, truncated}
            end

            S->>L: 提取发现
            Note right of L: 输入：搜索结果 + 页面内容
提取：关键信息 + 源 URL
评估：置信度 high/medium/low
            L-->>S: [{text, source, confidence}, ...]

            S->>S: 累积到 ResearchState
            Note right of S: addFinding({text, source, confidence})
addSource({url, title, snippet})
addSearchedQuery(query)
        end

        Note over U,W: ✅ Step 3: EVALUATE 评估
        Note over U,W: ══════════════════════════════════════════════════════════════

        S->>L: 评估研究完整性
        Note right of L: 输入：研究问题 + 累积发现
评估维度：
- 覆盖度：关键方面是否覆盖？
- 佐证：声明有多个源支持？
- 差距：有显著证据差距？
- 置信度：额外搜索会改变结论？
        L-->>S: {sufficient: true/false, gaps: [...], confidence: "..."}

        alt sufficient = true
            S->>S: ✅ 跳过剩余 depth level
        else sufficient = false AND depth < max_depth
            S->>L: 生成后续步骤
            Note right of L: 基于 gaps 生成
新的搜索方向
            L-->>S: [follow-up steps]
            Note right of S: 🔄 返回 Step 2 继续搜索
        else sufficient = false AND depth >= max_depth
            S->>S: ⚠️ 用现有发现继续
        end
    end

    Note over U,W: ══════════════════════════════════════════════════════════════
    Note over U,W: 📎 Step 4: CITE 引用验证
    Note over U,W: ══════════════════════════════════════════════════════════════

    loop 每个 finding
        S->>S: 验证源 URL
        Note right of S: ✅ URL 是否来自实际搜索结果？
✅ URL 是否可访问？

        S->>S: 附加引用
        Note right of S: 格式：[Title](URL)

        S->>S: 去重源
        Note right of S: 同一 URL = 一个条目

        alt source 为空
            S->>S: ⚠️ 标记 "uncited" + 警告
        end
    end

📋 五步流程详解

Step 1 PLAN 规划

职责：子智能体分析查询复杂度，生成结构化研究计划

输出：research_plan JSON（steps, breadth, depth）

LLM 调用：2 次（分析复杂度 + 生成计划）

用户参与：可选审核（submit_plan）

Step 2 SEARCH 搜索

职责：子智能体遍历计划步骤，并行执行搜索

工具：web_search（并行）+ web_fetch（深入阅读）

LLM 调用：N×2 次（生成查询 + 提取发现）

并行度：最多 3 个并发（REASONIX_PARALLEL_MAX）

Step 3 EVALUATE 评估

职责：评估研究完整性，决定是否继续迭代

评估维度：覆盖度、佐证、差距、置信度

LLM 调用：depth 次（每个 depth level 评估一次）

决策：足够→Step4 / 不足→Step2（迭代）

Step 4 CITE 引用验证

职责：验证源 URL，附加引用，去重源

规则：URL 必须来自实际搜索结果，不能伪造

LLM 调用：0 次（纯逻辑处理）

输出：带验证引用的发现列表

Step 5 REPORT 报告

职责：编译最终结构化报告

输出：摘要、发现、分析、源、置信度、元数据

LLM 调用：1 次（编译报告）

格式：Markdown，带内联引用
